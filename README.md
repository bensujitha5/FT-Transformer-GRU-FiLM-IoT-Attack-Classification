# FT-Transformer-GRU-FiLM for IoT Attack-Family Classification

## Overview

This repository presents a hybrid deep learning framework combining Feature Tokenizer Transformer (FT-Transformer), Gated Recurrent Unit (GRU), and Feature-wise Linear Modulation (FiLM) for intelligent IoT attack-family classification.

The proposed framework integrates Transformer-based feature interaction learning, gated token aggregation, and input-conditioned feature recalibration to classify malicious IoT network traffic into seven attack families.

The model is evaluated using the CIC-IoT 2023 dataset, with an additional independent training and evaluation experiment conducted on IoTID20.

## Proposed Architecture

The proposed FT-Transformer-GRU-FiLM framework consists of three principal components:

1. **FT-Transformer:** Processes the input network traffic features using patch-based tokenization and self-attention to learn feature interactions.
2. **GRU Aggregator:** Aggregates the three Transformer output tokens (CLS token and two feature-patch tokens) through gated updates.
3. **FiLM Module:** Performs input-conditioned feature-wise scaling and shifting to recalibrate the input representation.

The representations generated by the GRU and FiLM branches are concatenated and passed through a dense classification head to predict the attack family.

## Datasets

### 1. CIC-IoT 2023

The primary experiments use an attack-only subset of CIC-IoT 2023.

- Total records: 350,084
- Input features: 46
- Number of classes: 7
- Training/validation/testing split: 70:15:15
- Random seed: 42

Class mapping:

| Class ID | Attack Family |
|---|---|
| 0 | BruteForce |
| 1 | DDoS |
| 2 | DoS |
| 3 | Mirai |
| 4 | Recon |
| 5 | Spoofing |
| 6 | Web |

Benign traffic is excluded. Therefore, this experiment addresses closed-set seven-class attack-family classification rather than benign-versus-malicious intrusion detection.


### 2. IoTID20

The architecture is also evaluated independently on IoTID20.

- Approximate records: 625,783
- Original flow-level features: 80
- Selected input features: 46
- Number of classes: 5
- Training/validation/testing split: 70:15:15
- Training duration: 120 epochs

The five classes are Normal, DoS, Mirai, MITM (ARP spoofing), and Scan.

The 46 input features are selected using mutual-information ranking on the training subset.

**Note:** The IoTID20 model is trained from scratch. This experiment demonstrates architecture portability, not direct cross-dataset generalization.

## Experimental Results

### CIC-IoT 2023

The proposed framework achieved the following performance on the held-out test subset:

| Metric | Performance |
|---|---:|
| Accuracy | 98.63% |
| Precision (Macro) | 98.57% |
| Recall (Macro) | 98.51% |
| F1-score (Macro) | 98.54% |


## Model Configuration

| Parameter | Configuration |
|---|---|
| Input dimension | 46 |
| Feature patches | 2 × 23 |
| CLS token | 1 |
| Embedding dimension | 96 |
| Transformer layers | 3 |
| Attention heads | 4 |
| Feed-forward dimension | 192 |
| GRU units | 128 |
| FiLM branch units | 128 |
| Fusion dense units | 192 |
| Batch size | 1024 |
| CIC-IoT 2023 epochs | 100 |
| IoTID20 epochs | 120 |
| Optimizer | AdamW |
| Weight decay | 5 × 10⁻⁵ |
| Loss function | Sparse categorical cross-entropy |
| Random seeds | 42–46 for repeated experiments |
